## 전역 제약

1. **Flutter + Riverpod.** 의존은 `presentation → application → data → core` 단방향.
2. **`core/` 는 feature 를 모른다** — `lib/core/**` 가 `lib/features/**` 를 import 하면 위반(C-1).
3. **외부 패키지는 포트로 감싼다**(`core/*/spec/`+`impl/`). 화면이 `dio`·`stomp_dart_client`·`geolocator` 를 직접 import 하지 않는다.
4. **경로 문자열 리터럴 금지** — `AppRoutes` 상수로만(C-4).
5. **색·간격은 테마 상수만** — `AppColors`·`AppSpacing`·`textTheme` 경유. 매직넘버 금지(C-8).
6. **터치 48dp 이상**(`AppTouch.min`), 상태는 **색+아이콘+텍스트** 3중 표기(색만으로 구분 금지).
7. **낙관적 UI 금지** — 서버 응답 뒤에만 상태를 옮긴다. 기록도 정정도 예외 없다.
8. 명령은 `frontend/` 에서 — `flutter analyze`(무경고) · `flutter test` · `dart format --set-exit-if-changed lib/`.

- [ ] **Step 1: `RosterStudentTile` 의 콜백을 밖으로 뺀다** — 같은 행을 기사(읽기)와 선탑자(기록+정정)가 함께 쓴다. `required this.onAction` 을 아래 둘로 교체한다.

  ```dart
  /// 다음 동작을 기록한다. **null 이면 이 행은 읽기 전용**이다 — 기사 화면이 그렇다.
  /// 승하차 판정 주체가 선탑자로 옮겨졌다(OVERVIEW D-A).
  final ValueChanged<RideEventType>? onAction;

  /// 이미 남은 기록을 정정한다. null 이면 정정 버튼을 내지 않는다.
  /// 기사에게는 언제나 null 이다 — `POST /{id}/correction` 권한이 없다.
  final VoidCallback? onCorrect;
  ```

  `build` 에서 `final hasActionColumn = onAction != null || onCorrect != null;` 로 액션 열의 유무를 정하고, 가로 배치의 `SizedBox(width: _actionColumn, …)` 과 세로(확대) 배치의 `action` 을 그 조건으로 감싼다. **읽기 전용 행에는 열 자체를 두지 않는다** — 빈 112dp 를 남기면 이름이 왼쪽으로 쏠려 "뭔가 사라진 화면"으로 보인다.

  `isDone` 계산도 갈라야 한다 — 읽기 전용 행에는 "다음 동작"이라는 개념이 없다.
  ```dart
  final isDone = onAction == null
      ? student.nextActionFor(direction) == null
      : next == null && !isPending && !hasFailed;
  ```

- [ ] **Step 2: `_ActionArea` 에 정정 버튼을 얹는다** — `onAction` 을 nullable 로 받고 `onCorrect` 를 새로 받는다. 기존 반환값을 지역변수 `primary` 로 받되 `onAction == null` 이면 `primary = null` 이다. 정정 버튼은 기록 버튼 **아래**에 세로로 붙인다 — 옆에 두면 112dp 안에서 둘 다 잘리고, 오탭하면 잘못된 학부모 알림이 한 번 더 나간다.

  ```dart
  return Column(mainAxisSize: MainAxisSize.min,
    crossAxisAlignment: CrossAxisAlignment.stretch,
    children: [
      if (primary case final p?) p,
      if (onCorrect case final correct?) ...[
        if (primary != null) const SizedBox(height: AppSpacing.sm),
        // 전송 중에는 잠근다 — 같은 학생을 기록·정정으로 동시에 건드리면
        // 어느 응답이 최종인지를 서버 순서에 맡기게 된다.
        TextButton(
          onPressed: isPending ? null : correct,
          style: TextButton.styleFrom(
              minimumSize: const Size.fromHeight(AppTouch.min)),
          child: const Text('기록 수정')),
      ],
    ]);
  ```

- [ ] **Step 2: `RideEvent` 에 좌표를 싣고 정정 API 를 붙인다** — `RideEventDto` 는 이미 `stopId`·`lat`·`lng` 를 갖고 있는데 도메인이 버리고 있다. 정정 요청이 **원본 좌표를 되돌려 보내야** 하므로 살린다. `ride_event.dart` 에 `final int? stopId; final double? lat; final double? lng;` 를 추가하고 `fromDto` 에서 전달한다(표시용이 아니라 정정 요청용이라는 주석을 단다).

  ```dart

  /// 이미 남은 기록을 정정한다(`POST /api/ride-events/{id}/correction`).
  ///
  /// **원본을 덮어쓰지 않는다.** 서버가 `source=CORRECTION` 인 행을 새로 만들어
  /// 돌려주므로 화면은 응답의 `type` 으로만 상태를 옮긴다(낙관적 갱신 금지).
  ///
  /// ⚠️ `occurredAt` 은 **보내지 않는다** — 생략하면 서버가 원본 시각을 승계한다.
  /// 지금 시각을 실으면 정정할 때마다 "언제 탔는가"가 뒤로 밀린다.
  /// ⚠️ 반대로 [lat]·[lng] 는 **생략하면 원본 좌표가 null 로 사라진다**(`stopId`·
  /// `occurredAt` 과 폴백 규칙이 다르다 — `docs/API_SPEC.md` §승하차). 그래서
  /// 호출부가 원본 값을 그대로 실어 보낸다.
  Future<RideEvent> correct({required int eventId, required RideEventType type,
      int? stopId, double? lat, double? lng}) async {
    final dto = await _client.post('/api/ride-events/$eventId/correction',
        body: {'type': type.wireName, 'stopId': ?stopId, 'lat': ?lat, 'lng': ?lng},
        decode: Decode.one(RideEventDto.fromJson));
    final event = RideEvent.fromDto(dto);
    if (event == null) {
      throw const FormatException('알 수 없는 승하차 종류가 응답에 담겼습니다');
    }
    return event;
  }
  ```

- [ ] **Step 4: `DriverRosterController.correct()`** — `record()` 와 **같은 규칙**이다. 서버 응답 뒤에만 상태가 움직이고 전송 중인 학생은 잠긴다.

  ```dart
  /// 이미 남은 기록을 정정한다. 정정은 선탑자·관리자만 가능하다(§4.1).
  /// 잘못 누른 기록을 되돌릴 유일한 경로다 — 지금까지 프론트가 이 API 를
  /// 부르지 않아 오기록이 그대로 남았다.
  Future<void> correct(int studentId, RideEventType type) async {
    final before = state.value;
    if (before == null || before.isPending(studentId)) return;
    RideEvent? origin;
    for (final s in before.students) {
      if (s.studentId == studentId) origin = s.lastEvent;
    }
    if (origin == null) return;   // 정정할 대상 자체가 없다

    state = AsyncValue.data(
        before.copyWith(pending: {...before.pending, studentId}, clearError: true));
    try {
      final corrected = await ref.read(rideEventRepositoryProvider).correct(
          eventId: origin.id, type: type,
          stopId: origin.stopId, lat: origin.lat, lng: origin.lng);
      _finish(studentId, applied: corrected);
    } on ApiException catch (e) {
      _finish(studentId, error: e);
    } on FormatException catch (e) {
      _finish(studentId, error: e);
    }
  }
  ```

  `_finish` 는 그대로 쓴다 — `withEvent(corrected)` 가 상태와 `lastEvent` 를 함께 옮긴다.
