## 전역 제약

1. **Flutter + Riverpod.** 의존은 `presentation → application → data → core` 단방향. **`core/` 는 feature 를 모른다**(C-1).
2. **경로 문자열 리터럴 금지**(§8, C-4). 이 묶음은 `AppRoutes.adminMembers` 를 쓴다 — **`FE-1` 이 만든다**(아래 §전제 참조). `app_routes.dart`·`app_router.dart` 를 **이 묶음이 열지 않는다**(FE-P4 §병렬 안전선).
3. **색·간격은 테마 상수만** — `AppColors`·`AppSpacing`(`AppTouch` 포함, `lib/app/theme/app_spacing.dart:47`)·`textTheme`. `Color(0x…)`·`fontSize:` 금지(C-8).
4. **터치 48dp 이상**(`AppTouch.min`). **색만으로 상태를 구분하지 않는다** — 색 + 아이콘 + 텍스트 3중(DS §0-1).
5. **낙관적 UI 금지**(DS §0-2). 서버 응답 전에 목록을 미리 바꾸지 않는다. **삭제는 특히 그렇다** — 되돌릴 수 없다.
6. 명령은 `frontend/` 에서 — `flutter analyze`(무경고) · `flutter test` · `dart format --set-exit-if-changed lib/`.

## 전제 — `FE-1` 이 추가로 만들어야 하는 것 2가지

`FE-P4` 원본에는 **관리자 계정 관리 경로가 없다**(실측: `adminMembers` 문자열 0회). 이 묶음이 성립하려면 `FE-1` 이 다음 2개를 함께 만들어야 한다. **`FE-P4` §FE-1 에 이 두 줄이 반영돼 있는지 먼저 확인하고, 없으면 그 문서부터 고친다.**

```dart
// ① lib/app/router/app_routes.dart — 관리자 구역에 한 줄
static const adminMembers = '/admin/members';

// ② lib/app/router/app_router.dart — 관리자 셸 destinations 에 5번째 탭 + 5번째 branch
ShellDestination(label: '계정', icon: Icons.badge_outlined, selectedIcon: Icons.badge),
```

> ⚠️ **왜 모달이 아니라 라우트인가.** `FE-P5a2` 는 배차 인원 편집을 **모달**로 열었다(P5a2:11) — 그건 *배차 흐름 안에서* 잠깐 고치는 일이라 맥락을 떠나면 안 되기 때문이다. 계정 관리는 그 반대다. **그 자체가 목적지인 작업 공간**이고, 관리자가 학기 초에 30분씩 머무는 화면이다. 모달에 넣으면 어느 탭에서 열었느냐에 따라 뒤가 달라지고 새로고침하면 사라진다. **탭 하나를 내주는 것이 맞다.**

- [ ] **Step 1: `ApiClient` 에 `delete` 를 만든다. ⚠️ 이 묶음의 유일한 `core/` 편집이다.**

  실측: `ApiClient` 의 공개 메서드는 `get`·`post`·`patch` **셋뿐**이고, `frontend/lib` 전체에 HTTP DELETE 호출이 **0건**이다. `DELETE /api/members/{id}` 와 `DELETE /api/students/{id}` 를 부를 수단이 아예 없다.

  ```dart
  // lib/core/api/api_client.dart — patch 아래에 이어 붙인다
  Future<T> delete<T>(
    String path, {
    required T Function(Object? data) decode,
  }) {
    return _send(() => _dio.delete<dynamic>(path), decode);
  }
  ```

  ⚠️ **클래스 doc 주석(줄 16)도 같이 고친다.** 지금 *"repository 는 `get`/`post`/`patch` 만 쓰고"* 라고 **계약을 명시**하고 있다 — 코드만 늘리고 주석을 두면 다음 사람이 주석을 믿는다. `get`/`post`/`patch`/`delete` 로 고친다.

  ⚠️ `body` 파라미터를 두지 않는다. 이 묶음이 부르는 DELETE 두 개는 본문이 없고, 쓰지 않는 매개변수는 **"본문을 실어도 되는가"** 라는 잘못된 신호가 된다.

  ⚠️ **`api_client_test.dart` 에 회귀 1건을 더한다** — 응답 봉투 해제와 `ApiException` 변환이 `delete` 에서도 같은지. `_send` 를 공유하므로 통과하는 게 정상이지만, 나중에 `delete` 만 따로 구현하는 사고를 막는다.

  > `api_client.dart` 는 **병렬 안전선 목록에 없다**(FE-P4:550 은 `role.dart`·`app_routes.dart`·`role_redirect.dart`·`app_router.dart`·`core/ui/person_*.dart` 5개다). `FE-P5a2:267` 이 *"`api_client.dart` 는 고치지 않는다"* 라고 적은 것은 **그 묶음의 두 엔드포인트가 둘 다 POST 라서**지 금지가 아니다. 전제가 다르므로 여기서는 고친다. **단 이 묶음 말고는 아무도 이 파일을 열지 않는다.**

- [ ] **Step 2: DTO — `BE-12` 응답을 글자 그대로 옮긴다.** 필드명을 지어내지 않는다(근거 OVERVIEW §4.6, `BE-P2b` Step 3·4).

  | 클래스 | 필드 |
  |---|---|
  | `MemberDto` | `userId` · `email` · `name` · `phone?` · `photoUrl?` · `role`(wire 문자열) · `tenantId?` |
  | `MemberDetailDto` | `MemberDto` 의 전 필드 + `List<BusRefDto> assignedBuses` · `List<StudentRefDto> guardedStudents` |
  | `BusRefDto` | `busId` · `plateNumber` · `asAttendant`(bool) |
  | `StudentRefDto` | `studentId` · `name` · `relation?` |

  `role` 은 **`Role.fromWire(json['role'])`** 로 도메인 enum 으로 바꿔 담는다. 문자열로 들고 다니면 화면마다 `== 'DRIVER'` 비교가 생긴다.
  ⚠️ `Role.fromWire` 는 모르는 값에 **`null`** 을 준다. 서버가 새 역할을 추가했을 때 앱이 죽지 않게 하려는 설계다 — `MemberDto.role` 을 `Role?` 로 두고, 화면은 null 이면 **`역할 미상`** 으로 그린다. `?? Role.student` 같은 기본값으로 **덮지 않는다**(C-2: 근거 없는 기본값으로 결손 은폐 금지).

  `student_dto.dart` 의 `StudentDto` 에 **4개를 추가**한다(`BE-13` Step 4): `phone?` · `photoUrl?` · `active`(bool) · `pickupAddress?`.
  ⚠️ `active` 는 **non-null 로 받는다.** `bool?` 로 두면 화면이 "모르는 상태"를 그려야 하는데, 서버는 항상 값을 준다(`not null default true`).

- [ ] **Step 3: `MemberRepository` — 5개 메서드.** 서버가 하나뿐이라 포트로 나누지 않는다(CONV §5).

  ```dart
  class MemberRepository {
    const MemberRepository(this._client);
    final ApiClient _client;

    /// 학원 구성원 목록. role 을 주면 그 역할만.
    Future<List<MemberDto>> list({required int tenantId, Role? role}) =>
        _client.get('/api/members',
            query: {'tenantId': tenantId, 'role': role?.wireName},   // null 은 _clean 이 뺀다
            decode: Decode.list(MemberDto.fromJson));

    Future<MemberDetailDto> detail(int userId) => _client.get(
        '/api/members/$userId', decode: Decode.one(MemberDetailDto.fromJson));

    Future<MemberDto> create(CreateMemberBody body) => _client.post(
        '/api/members', body: body.toJson(), decode: Decode.one(MemberDto.fromJson));

    Future<MemberDto> update(int userId, UpdateMemberBody body) => _client.patch(
        '/api/members/$userId', body: body.toJson(), decode: Decode.one(MemberDto.fromJson));

    /// 학원 멤버십 해제. 계정 자체는 서버에 남는다(OVERVIEW D-O).
    Future<void> removeMembership(int userId) =>
        _client.delete('/api/members/$userId', decode: Decode.unit);

    Future<void> resetPassword(int userId, String newPassword) => _client.patch(
        '/api/members/$userId/password',
        body: {'newPassword': newPassword}, decode: Decode.unit);
  }

  final memberRepositoryProvider = Provider<MemberRepository>(
    (ref) => MemberRepository(ref.watch(apiClientProvider)));
  ```

  ⚠️ **`Decode.unit` 이다.** 실측한 헬퍼 이름은 `one`·`list`·`unit` 셋이다 — `Decode.object` 는 **없다.**
  `student_repository.dart` 에도 같은 모양으로 `detail`·`create`·`updateProfile`·`deactivate` 를 더한다. 목록 조회에 `includeInactive` 를 붙인다(`BE-13` Step 7).

- [ ] **Step 4: 컨트롤러 — 패턴 ②(`isSubmitting` + `actionError`)를 쓴다.**

  저장소에 쓰기 패턴이 두 갈래로 존재한다. **여기서는 ②다.**

  | 패턴 | 선례 | 이 화면에 맞는가 |
  |---|---|---|
  | ① `state = const AsyncValue.loading()` 후 `AsyncValue.guard` | `AdminDispatchController` | ❌ 한 건 저장에 **목록 전체가 사라졌다 나타난다** |
  | ② 상태에 `isSubmitting`·`actionError` 를 두고 화면은 유지 | `DriveSessionController:103-165` | ⭕ |

  ```dart
  /// 계정 관리 목록 한 화면의 상태. 탭(=역할)마다 따로 두지 않고 하나로 둔다 —
  /// 탭을 옮길 때마다 새 컨트롤러가 뜨면 방금 만든 계정이 안 보인다.
  class MemberListState {
    final MemberTab tab;                 // student | parent | driver | attendant
    final List<MemberDto> members;       // 구성원 3탭이 쓴다
    final List<StudentDto> students;     // 학생 탭이 쓴다
    final bool includeInactive;          // 학생 탭 전용
    final int? selectedId;               // 우측 상세 패널이 보는 대상
    final bool isSubmitting;             // 저장 중 — 버튼만 잠그고 목록은 그대로 둔다
    final ApiException? actionError;     // 인라인 배너로만 낸다
  }
  ```

  ⚠️ **`ref.invalidate` 로 목록을 통째로 다시 받지 않는다.** 삭제·수정 직후 `invalidate` 하면 스켈레톤이 한 번 번쩍이고 관리자가 방금 고친 줄을 다시 찾아야 한다. **서버 응답으로 받은 한 줄만 교체**한다(`removeMembership` 은 응답이 없으므로 그 id 만 제거).

  ⚠️ **낙관적 UI 금지(DS §0-2).** 목록에서 먼저 지우고 요청을 보내면 **409(참조 중)** 가 돌아왔을 때 이미 사라진 줄을 되살려야 한다. 반드시 **응답 뒤에** 지운다.

**목적:** 학생과 보호자를 **손으로 잇고 끊는다.** 지금은 잇는 API 만 있고(`POST /api/students/{id}/guardians`) 화면도 없다.

**선행:** **`FE-11`**(같은 화면·같은 컨트롤러를 확장한다 — 순차) · `BE-14`.

**Files**

- [ ] **Step 1: 리포지토리 3개.**

  Future<StudentDetailDto> linkGuardian(int studentId, {required int guardianUserId, String? relation}) =>
      _client.post('/api/students/$studentId/guardians',
          body: {'guardianUserId': guardianUserId, 'relation': relation},
          decode: Decode.one(StudentDetailDto.fromJson));

## 인계 — 다음 사람이 알아야 할 것 4가지

1. **`ApiClient.delete` 는 이 묶음이 만들었다.** `api_client.dart` doc 주석의 계약 문구도 함께 고쳤다. 다른 묶음은 이 파일을 열지 않는다.
2. **폼·파괴적 확인은 이 묶음이 저장소의 첫 선례다.** `login_screen.dart` 를 베낀 `Form` 구조와 `DestructiveConfirm`(다이얼로그 아님)이 그것이다. `DESIGN_SYSTEM.md` 에 대응 조항이 **없으므로**, `DOC-*` 단계에서 §5.1 공용 위젯 표에 `DestructiveConfirm` 을 추가할지 결정해야 한다.
3. **feature 교차 참조가 세 번째로 늘었다**(`user/presentation → student/application`). FE-P4:558 이 예고한 `shared/domain/` 승격 결정 시점이다.
4. **`AppRoutes.adminMembers` 와 관리자 5번째 탭은 `FE-1` 산출물이다.** 이 묶음은 `app_routes.dart`·`app_router.dart` 를 열지 않았다.
