## ★ 먼저 읽을 것 — 지도에 자녀 마커는 없다

**학부모 지도에 올리는 것은 버스 위치뿐이다.** 자녀(학생) 본인의 좌표는 **표시하지 않는다**(OVERVIEW D-F).

이유: 학생 좌표를 서버로 올리는 주체는 학생 앱인데 이번 범위에 학생 앱이 없다. 그래서 `GET /api/locations/children` 은 **호출해도 항상 빈 배열**이다(`docs/API_SPEC.md` §412 — "최신 좌표가 없는 자녀는 결과에서 조용히 제외된다"). 이 API 를 부르는 코드를 만들지 마라. 마커가 안 보이는 게 아니라 **데이터가 원천적으로 없다.**

**구현 순서.** ID 는 OVERVIEW 가 정한 것이고, **실제 구현 순서는 `FE-8` → `FE-7` → `FE-9` → `FE-10`** 이다. `FE-8` 이 만드는 `parentChildrenProvider`(자녀 명단·이름)를 `FE-7` 이 읽기 때문이다(`FE-8` Step 5 참고).

## 전역 제약

- Flutter + Riverpod. `presentation → application → data → core` **단방향**이다. 역방향 import 금지.
- `core/` 는 어떤 feature 도 알지 않는다. `core/map`·`core/ws` 에 학부모 지식을 넣지 마라.
- 외부 패키지는 포트(`core/*/spec/`) + 구현(`core/*/impl/`) 뒤에 둔다. 화면·컨트롤러는 `dio`·`stomp_dart_client`·`flutter_map` 을 import 하지 않는다.
- 경로 문자열 리터럴 금지 — `AppRoutes` 상수만 쓴다.
- 색·간격·반경은 `app/theme` 토큰(`AppColors`·`AppSpacing`)과 `AppTone` 만 쓴다. `Color(0x…)`·`TextStyle(fontSize:)`·숫자 리터럴 여백 금지.
- 탭 가능한 요소는 **48dp 이상**(`AppTouch.min`).
- **색만으로 상태를 구분하지 않는다** — 아이콘 문자 + 한글 라벨을 항상 같이 낸다(`DESIGN_SYSTEM.md` §0-1).
- **낙관적 UI 금지** — 서버 응답 전에 결과를 확정 표시하지 않는다(§0-2).
- 에러 분기는 **HTTP status 로만** 한다. `message` 문자열 파싱 금지. 서버 `message` 는 그대로 보여준다.
- `AsyncValue` 는 `core/ui/async_section.dart` 의 `AsyncSection<T>` 를 거쳐 loading/error/data 세 갈래를 전부 그린다.
- 빈 배열은 에러가 아니다 — `EmptyView` 로 그리고 **다음 행동**을 준다.
- 명령은 전부 `frontend/` 에서: `flutter analyze` (무경고) · `flutter test` · `dart format --set-exit-if-changed lib/`.
- **커밋 규칙은 [OVERVIEW §1.5](../../../docs/plans/2026-08-02-mvp-확장-OVERVIEW.md) 하나뿐이다** — 여기서 다시 정의하지 않는다. 각 태스크의 마지막 단계에는 **그 태스크의 커밋 메시지**만 적어 뒀다. 태스크 안에서 더 잘게 나눠 커밋해도 좋고, 커밋 전에 `flutter analyze && flutter test` 를 통과시키는 것은 §1.5 가 이미 요구한다. 본문 끝에는 저장소 관례대로 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>` 를 붙인다.

  ```dart
  class ParentLocationRepository {
    /// 학부모 개인 큐. Spring user-destination 이 세션 단위로 격리하므로
    /// 추가 인가 검사가 없다(학원 topic 과 다르다).
    static const _busQueue = '/user/queue/bus-location';

    /// 자녀가 배정된 버스들의 최신 위치. 빈 배열은 정상이다(배차 전).
    Future<List<ChildBus>> childrenBuses() async {
      final dtos = await _client.get(
        '/api/locations/children/buses',
        decode: Decode.list(ChildBusLocationDto.fromJson),
      );
      final observedAt = DateTime.now();
      return [for (final dto in dtos) ChildBus.fromDto(dto, observedAt: observedAt)];
    }

    /// 구독 시작 **이후** 도착분만 온다. 현재 상태는 [childrenBuses] 로 채운다.
    Stream<BusLocationDto> watchMyBuses() =>
        _gateway.subscribe(_busQueue).map(BusLocationDto.fromJson);
  }
  ```

- [ ] **Step 5: `parentChildrenProvider` 를 만든다.**
  **왜 여기 있는가** — 학부모가 자녀 **이름**을 얻을 수 있는 API 가 `BE-9` 응답뿐이다. `GET /api/students` 는 `ACADEMY_ADMIN` 전용이고, `GET /api/ride-events/children` 은 `studentId` 만 준다(`docs/API_SPEC.md` §713). 그래서 이름 사전을 이 feature 가 갖고, `FE-7` 이 **읽기만** 한다.
  ```dart
  /// studentId → 자녀 이름. `FE-7`(학부모 홈)이 카드 제목에 쓴다.
  ///
  /// ⚠️ 이름을 못 얻어도 홈 화면은 그려져야 한다 — 소비자는 `AsyncValue` 를 그대로
  /// 받아 loading·error 일 때 `학생 #{id}` 로 대체한다. 여기서 빈 Map 으로
  /// 뭉개면 "이름을 아직 못 받음"과 "이름이 없음"을 구분할 수 없다.
  final parentChildrenProvider = Provider<AsyncValue<Map<int, String>>>((ref) {
    return ref.watch(parentBusMapControllerProvider).whenData(
      (state) => {
        for (final bus in state.buses)
          for (final child in bus.children) child.studentId: child.name,
      },
    );
  });
  ```
- [ ] **Step 6: `ParentBusMapController` — REST 로 채우고 STOMP 로 갱신한다.**
  **본뜬 파일: `lib/features/notification/application/notification_feed_controller.dart`.** 그 파일 주석의 4단계 순서를 그대로 따른다 — ① 구독 범위 결정 ② **REST 로 현재 상태 먼저** ③ STOMP 를 붙여 도착분만 반영 ④ 화면을 벗어나면 구독·연결 정리.
  ⚠️ **STOMP 는 연결된 동안 오는 것만 준다.** 첫 진입 시 REST 를 건너뛰면 버스가 다음 보고(최대 3초)까지 지도에 없다.
  `class ParentBusMapController extends AutoDisposeAsyncNotifier<ParentBusMapState>` 의 본문은 아래와 같다.
  `ParentBusMapState{ List<ChildBus> buses, StompConnectionState connection, Object? liveError, DateTime? updatedAt }` + `copyWith` + `bool get isEmpty` + `List<GeoPoint> get focusPoints`(위치 있는 버스 좌표만).
  `liveError` 가 있어도 **이미 받은 좌표는 지우지 않는다** — 깜빡이기만 하고 정보는 줄어든다.
  ```dart
  @override
  Future<ParentBusMapState> build() async {
    final repository = ref.read(parentLocationRepositoryProvider);
    final gateway = ref.read(stompGatewayProvider);

    // (2) 현재 상태 먼저. 실패하면 화면 전체가 에러다 — 보여줄 게 없다.
    final buses = await repository.childrenBuses();

    final connectionSub = gateway.states.listen(_onConnectionChanged);
    final feedSub = repository.watchMyBuses().listen(_onMoved, onError: _onLiveError);

    // (4) 화면을 벗어나면 구독과 소켓을 모두 정리한다(포트 문서의 누수 방지 규칙).
    ref.onDispose(() {
      connectionSub.cancel();
      feedSub.cancel();
      gateway.disconnect();
    });
    unawaited(gateway.connect());

    return ParentBusMapState(
      buses: buses, connection: gateway.state, updatedAt: DateTime.now(),
    );
  }

  void refresh() => ref.invalidateSelf();   // 구독까지 다시 만든다

  /// 자녀 버스가 아닌 busId 는 무시한다. 서버가 보내지 않겠지만, 들어온 걸
  /// 새 버스로 추가하면 이름·자녀 정보가 없는 유령 항목이 생긴다.
  void _onMoved(BusLocationDto dto);
  void _onLiveError(Object error);
  ```

  ```dart
        icon: '✓', tone: AppTone.success,
        title: '노선에 반영했습니다',
        body: '새 위치를 넣어 노선을 다시 계산했고 기사에게도 전달했습니다.',
        nextAction: DecisionNextAction.viewHistory),
      LocationChangeDecision.rejected => const DecisionCopy(
        icon: '!', tone: AppTone.warning,
        title: '이번 위치로는 반영되지 않았습니다',
        body: '노선이 너무 많이 늘어나 자동 반영 기준(소요시간 5분·거리 1km 이내)을 넘었습니다. '
              '가까운 다른 위치로 다시 신청하거나, 학원에 직접 문의해 조정할 수 있습니다.',
        nextAction: DecisionNextAction.retryWithAnotherPoint),
      LocationChangeDecision.blocked => const DecisionCopy(
        icon: '✕', tone: AppTone.error,
        title: '오늘은 접수할 수 없습니다',
        body: '해당 날짜의 운행이 이미 시작되어 위치를 바꿀 수 없습니다. 다른 날짜로 신청해 주세요.',
        nextAction: DecisionNextAction.changeDate),
    };
  ```
  `enum DecisionNextAction { viewHistory, retryWithAnotherPoint, changeDate }` — 결과 화면의 다음 행동. **막다른 길을 만들지 않는다.**
  `REJECTED` 응답에 `deltaDurationS`·`deltaDistanceM` 이 있으면 본문 아래에 `예상 증가: +7분 · +1.4km` 를 덧붙인다. **없으면 붙이지 않는다**(수치를 지어내지 마라).
- [ ] **Step 3: DTO 와 repository 를 만든다.**
  - 요청 `LocationChangeRequestDto.toJson()` → `{studentId, direction: wireName, serviceDate: 'yyyy-MM-dd', lat, lng, address, reason}`
  - 응답 `LocationChangeResultDto{ int id, int studentId, String direction, String serviceDate, double lat, double lng, String address, String? reason, String decision, double? deltaDistanceM, double? deltaDurationS }` — `GET .../children` 의 원소와 같은 형태다. `decision` 은 `APPLIED`/`REPLANNED`/`REJECTED`/`BLOCKED`. **delta 는 서버가 안 주면 null 이며 화면이 임의로 채우지 않는다.**
  `ApiClient.post` / `get` 만 쓴다(`put`·`delete` 는 존재하지 않고 필요하지도 않다).
  ⚠️ **`BLOCKED` 를 4xx 로 받을 수도 있다.** 그 경우 `ApiException` 이 나고 서버 `message` 가 그대로 표시되는 기존 에러 경로로 떨어진다 — 동작은 하지만 안내 문구가 §Step 2 의 것과 달라진다. **`BLOCKED` 도 `200` + `decision: "BLOCKED"` 로 내려주도록 `BE-10` 과 합의한다**(§자체 점검 2-③). status 로 `BLOCKED` 를 추론하거나 `message` 를 파싱해 분기하지 마라(컨벤션 §7-1).
- [ ] **Step 4: "현재 위치"를 방향별로 다르게 읽는다.**
  새 좌표가 서버에서 어느 컬럼으로 들어가는지(등원→`pickup_*`, 하원→`dropoff_*`)는 프론트가 알 필요 없다. **하지만 "지금은 어디로 돼 있나"를 보여줄 때는 방향에 따라 다른 값을 읽어야 한다.** 안 그러면 등원 신청 화면에 하차 주소가 뜨고, 사용자는 자기가 바꾸려는 게 뭔지 알 수 없다.
  갈래가 셋이다. `CurrentChildLocation` 이 이 셋을 구분해 담는다 — **하나로 뭉개면 "직접 지정한 위치"와 "정류장 배정"이 같아 보인다.**

  | 방향 | 자녀 데이터 | `source` | 지도 | 라벨 |
  |---|---|---|---|---|
  | 등원 | `pickup_lat/lng` 있음 | `ownCoordinate` | 그 좌표에 마커 | `현재 등원 위치 · {pickupAddress}` |
  | 등원 | `pickup_*` 없고 `boardingStop` 만 있음 | `sharedStop` | **정류장 좌표**에 마커 | `현재 배정 정류장 · {정류장 이름}` |
  | 하원 | `dropoff_lat/lng` | `ownCoordinate` | 그 좌표에 마커 | `현재 하원 위치 · {dropoffAddress}` |
  | 둘 다 | 값을 못 받음 | `unknown` | 마커 없음 | `현재 지정된 위치를 불러오지 못했습니다` |

  ⚠️ **`pickup_*` 좌표가 있으면 그것이 우선이다**(D-K). 좌표와 `boardingStop` 이 둘 다 있어도 `sharedStop` 으로 그리지 마라 — 서버 판단 순서와 화면 표시가 어긋나면 사용자가 "바꿨는데 안 바뀌었다"고 읽는다.
  `sharedStop` 일 때는 마커 아래에 한 줄 덧붙인다: `이 정류장은 다른 학생과 함께 씁니다. 새 위치를 지정하면 자녀만 옮겨집니다.` — D-K 가 고치려던 오해를 화면에서 미리 막는다.
  값은 `FE-8` 의 `ChildOnBus` 선택 필드에서 읽는다. 판정은 순수 함수 하나로 끝난다.
  ```dart
  // lib/features/schedule/application/current_child_location_provider.dart
  CurrentChildLocation resolve(ChildOnBus child, ChangeDirection direction) {
    final own = direction == ChangeDirection.pickup
        ? (child.pickupPoint, child.pickupAddress)
        : (child.dropoffPoint, child.dropoffAddress);
    if (own.$1 != null) {
      return CurrentChildLocation(
          source: CurrentLocationSource.ownCoordinate,
          point: own.$1, label: own.$2);
    }
    // 등원만 해당한다 — 하원은 공유 정류장 개념이 없다.
    if (direction == ChangeDirection.pickup && child.boardingStopPoint != null) {
      return CurrentChildLocation(
          source: CurrentLocationSource.sharedStop,
          point: child.boardingStopPoint, label: child.boardingStopName);
    }
    return const CurrentChildLocation(source: CurrentLocationSource.unknown);
  }
  ```
  ⚠️ **이 필드들을 실제로 내려주는 API 가 아직 없다.** `PARENT` 권한으로 자녀의 `pickup_*`/`dropoff_*`/`boardingStop` 을 읽는 엔드포인트가 OVERVIEW §4.2 에 없다(§자체 점검 2-⑥). 확정 전까지는 `unknown` 갈래만 실제로 동작한다 — **그 상태에서도 신청 자체는 되어야 한다.** 현재 위치를 못 보여준다고 폼을 막지 마라.
- [ ] **Step 5: `LocationPickerMap` — 지도에서 좌표를 찍는다.**
  `FE-8` Step 1 이 넣은 `MapViewAdapter.build(onTap:)` 을 쓴다. 화면은 `flutter_map` 을 모른다.
  현재 위치를 아는 경우(Step 4) **현재 마커와 새 마커를 둘 다** 올리고 모양으로 구분한다 — 현재는 `MapMarkerKind.visitedStop`, 새로 찍은 곳은 `MapMarkerKind.stop`(채운 원). 색만으로 나누지 않는다(§0-1).
  카메라 `focus` 는 **처음 열 때 현재 위치**, 좌표를 찍은 뒤에는 두 점이 다 들어오게 준다.
  ```dart
  ref.watch(mapViewAdapterProvider).build(
  ```

  ⚠️ **주소는 좌표에서 자동으로 나오지 않는다.** 저장소에 역지오코딩 수단이 없다(지도는 OSM 타일만 쓴다). 주소는 **사용자가 직접 입력**하는 필수 텍스트 필드이며, 지도 탭은 좌표만 채운다. 화면 안내 문구: `지도를 눌러 위치를 고르고, 아래에 주소를 적어 주세요.`
- [ ] **Step 6: 폼 컨트롤러와 화면을 만든다.**
  입력 순서: **자녀 선택 → 방향(등원/하원) → 날짜 → 지도에서 좌표 → 주소 → 사유.**
  - **방향 선택은 `ChangeDirection.values` 를 그대로 돌려 만든다.** 둘 다 항상 선택 가능해야 하므로, 한쪽을 `enabled: false` 로 두거나 조건부로 감추는 코드를 넣지 마라(D-K).

  - 날짜는 **오늘 이후**만 고를 수 있게 한다. 과거 날짜는 서버가 어차피 거부하고, 사용자에게 되돌릴 수 없는 실패를 겪게 할 이유가 없다.
  - `LocationChangeFormState` 는 `{ int? studentId, ChangeDirection direction, DateTime serviceDate, GeoPoint? point, String address, String reason, bool submitting, LocationChangeResultDto? result, Object? error }`.

  - 응답이 오면 `DecisionResultView` 로 교체한다. **4갈래 전부 결과 화면**이고, `AppStatusChip(icon:, label:, tone:)` 로 결과를 표시해 색만으로 구분하지 않는다.
  - `DecisionNextAction` 별 버튼: `viewHistory` → 이력 목록(`GET .../children`) 펼치기 · `retryWithAnotherPoint` → 좌표만 비우고 폼 복귀 · `changeDate` → 날짜 필드에 포커스를 둔 폼 복귀.

| P1 버스 실시간 위치 | `FE-8` — REST(`BE-9`)로 현재 상태를 채우고 STOMP(`BE-8`)로 갱신. 자녀 버스 좌표에 카메라를 맞추는 `focus` 포트 확장 포함 |
| P1 "왜 안 움직이지" 구분 | `FE-10` — 기존 `ConnectionStatusChip` 을 `core/ui/` 로 옮겨 재사용 |
| P2 위치 변경 신청 | `FE-9` — 자녀·방향·날짜·좌표·주소·사유 입력, `BE-10` 제출 |
| P2 **등원·하원 둘 다** | `FE-9` Step 1·4·6 — D-K 로 등원 좌표가 학생 자체 컬럼이 됐으므로 방향 선택은 항상 2지선다다. 방향별로 "현재 위치"를 다른 값에서 읽고, 등원에 `pickup_*` 이 없으면 `boardingStop` 으로 떨어뜨려 **정류장 배정임을 명시**한다 |
| P2 4갈래 자동 판정 | `FE-9` Step 2 — `APPLIED`/`REPLANNED`/`REJECTED`/`BLOCKED` 각각의 문구·톤·**다음 행동**을 코드 한 곳(`DecisionCopy`)에 고정 |

**덮지 않는 것:** 자녀 위치 마커(D-F 로 범위 밖) · 학부모 알림함(`GET /api/notifications/children` 은 이번 4개 태스크에 없다) · 결석 신고 · SOS.

### 2. 백엔드와 합의가 더 필요한 지점

1. **`BE-9` 응답 필드 (차단성 있음).** OVERVIEW §4.2 는 경로·권한만 정하고 **DTO 를 정의하지 않았다.** 이 문서는 `[{busId, busName, lat?, lng?, recordedAt?, origin?, children:[{studentId, studentName}]}]` 를 가정했다. 특히 **`children[].studentName` 이 없으면 `FE-7` 이 자녀 이름을 표시할 방법이 사라진다** — 아래 3-① 참고. 확정 전까지 `FE-8` Step 3 의 DTO 를 최종으로 보지 마라.
2. **`BE-8` push payload.** `/user/queue/bus-location` 이 `GET /api/locations/buses` 원소(`BusLocationDto`: `busId, busName, lat, lng, recordedAt, origin`)와 **같은 형태**라고 가정하고 `BusLocationDto.fromJson` 을 재사용했다. 다르면 `ParentLocationRepository.watchMyBuses()` 의 `map` 만 바꾸면 되지만, 계약을 먼저 확인할 것.
3. **`BLOCKED` 의 HTTP status.** OVERVIEW §4.4 는 `BLOCKED` 를 `LocationChangeDecision` 값으로 정의했지만 **응답 status 를 명시하지 않았다.** 4xx 로 오면 `ApiException` 경로로 떨어져 `FE-9` Step 2 가 정한 안내 문구·다음 행동이 나오지 않는다. **`200` + `decision: "BLOCKED"` 로 통일해 달라고 요청한다.** (추측으로 status 분기를 넣지 않았다.)
4. **`REJECTED` 의 delta 노출 여부.** 사용자에게 "얼마나 초과했는지"를 보여주려면 `deltaDurationS`·`deltaDistanceM` 이 응답에 있어야 한다. 없으면 `FE-9` 는 수치 없이 문구만 낸다(지어내지 않는다).
5. **`occurredAt` 타임존.** 서버가 `LocalDateTime` 을 오프셋 없이 직렬화해 절대 시각을 신뢰할 수 없다. `FE-7` 은 그래서 시각을 아예 표시하지 않기로 했다. `OffsetDateTime`/`Instant` 로 바뀌면 시각 표시를 되살릴 수 있다 — 별도 태스크로 남긴다.
6. **자녀의 "현재" 등하원 위치를 읽을 API 가 없다 (D-K 로 새로 생긴 구멍).** D-K 가 `pickup_lat/lng/address` 를 추가하면서 `FE-9` 는 **방향별로 다른 현재 위치를 보여줘야** 하는데, `PARENT` 권한으로 그 값을 읽는 엔드포인트가 OVERVIEW §4.2 신규 6개 어디에도 없다. `GET /api/location-change-requests/children` 은 **과거 신청 이력**이라 기준값이 될 수 없다(신청한 적 없는 자녀는 아무것도 안 나온다).
   필요한 최소 응답: `{studentId, pickupLat?, pickupLng?, pickupAddress?, boardingStopName?, boardingStopLat?, boardingStopLng?, dropoffLat?, dropoffLng?, dropoffAddress?}`.
   가장 싼 해결은 **`BE-9` 응답의 `children[]` 에 이 필드를 얹는 것**이다 — 학부모가 이미 부르는 엔드포인트이고, 1-① 의 `studentName` 문제도 같이 풀린다. 확정 전까지 `FE-9` 는 `CurrentLocationSource.unknown` 으로 그리며, **그 상태에서도 신청 자체는 된다**(현재 위치를 못 보여준다고 폼을 막지 않았다).

### 3. 소스를 읽다 발견한, 계획과 어긋나는 사실

1. **학부모가 자녀 이름을 얻을 API 가 없다.** `GET /api/students` 는 `ACADEMY_ADMIN`·`PLATFORM_ADMIN` 전용이고(`features/student/data/student_repository.dart`), `GET /api/ride-events/children` 은 `studentId` 만 준다(`docs/API_SPEC.md` §713). `PARENT` 권한 엔드포인트 목록(§1895~1957)에도 학생 명단은 없다. 그래서 이 문서는 **`BE-9` 응답에 자녀 이름을 실어 달라**는 전제로 설계했고, 못 받으면 `학생 #{id}` 로 떨어지게 안전장치를 넣었다. 대안(더 깔끔): `RideEventResponse` 에 `studentName` 을 **추가**(기존 필드 제거 없음 → 기사·선탑자 앱 무영향). 둘 중 하나는 반드시 정해야 한다.
2. **지도 기본 중심 하드코딩은 "설정값"이 아니라 "맞출 대상이 없을 때의 폴백"이다.** `FlutterMapAdapter._fallbackCenter`(`flutter_map_adapter.dart:15`)는 `_fit()` 이 null 일 때만 쓰이는데, `_fit()` 은 `MapMarkerKind.bus` 를 **의도적으로 제외**한다(`:150-153`, 카메라 리셋 방지). 즉 **버스 마커만 있는 학부모 지도는 구조적으로 항상 폴백에 걸린다.** 상수만 바꿔서는 안 고쳐지고, `FE-8` Step 1~2 의 `focus` 포트 확장이 필요하다.
3. **`ChangeDirection` 은 세 번째 중복 정의다.** `RouteDirection`(`features/routing/domain/route_plan.dart:8`)과 `DriveDirection`(`features/drivesession/domain/drive_session.dart:10`)이 이미 `PICKUP`/`DROPOFF` 를 각각 갖고 있다. 이번엔 feature 간 결합을 피해 또 하나 만들지만, 정리하려면 `shared/domain/` 으로 올려야 한다 — `FE-6`(관리자 배차) 담당과 파일이 겹치므로 **이번 묶음에서 손대지 않는다.**
4. **`Role.parent.isSupportedInMvp` 가 현재 `false` 다**(`lib/shared/domain/role.dart`). 학부모 계정으로 로그인하면 "지원하지 않는 역할" 안내가 뜬다. `FE-1` 이 이걸 푸는 것을 전제로 했다 — `FE-1` 이 안 고치면 이 묶음의 화면에 **도달 자체가 불가능**하다.
5. **`NotificationFeedController._FeedScope` 가 학부모를 개인 큐로만 처리한다**(`role.dart` 주석 및 `notification_feed_controller.dart:211`). `/user/queue/bus-location` 은 별도 목적지라 충돌하지 않지만, `StompGateway` 는 **연결이 하나**다. 학부모가 알림함과 지도를 동시에 열면 두 컨트롤러가 각각 `ref.onDispose` 에서 `gateway.disconnect()` 를 호출해 **한쪽이 다른 쪽의 소켓을 끊는다.** 이번 묶음은 학부모 알림함 화면을 만들지 않아 실제로 부딪히지 않지만, 학부모 알림함을 추가할 때 반드시 먼저 해결해야 한다(참조 카운팅 또는 게이트웨이 소유권 이전).
