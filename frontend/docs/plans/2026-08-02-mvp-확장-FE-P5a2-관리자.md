## 전역 제약

1. **Flutter + Riverpod.** 의존은 `presentation → application → data → core` 단방향. **`core/` 는 feature 를 모른다**(C-1).
2. **외부 패키지는 포트로 감싼다** — `core/*/spec/` + `core/*/impl/`(§5). 화면·도메인이 `flutter_map`·`dio` 를 import 하지 않는다.
3. **경로 문자열 리터럴 금지**(§8, C-4). ⚠️ 이 묶음은 **새 라우트를 만들지 않는다** — `app_routes.dart`·`app_router.dart` 는 `FE-1` 이후 아무도 편집하지 않는다(FE-P4 §병렬 안전선). 인원 편집·비교는 **모달**로 연다.
4. **색·간격은 테마 상수만** — `AppColors`·`AppSpacing`·`AppTouch`·`textTheme`. `Color(0x…)`·`fontSize:`·매직넘버 금지(C-8).
5. **터치 48dp 이상**(`AppTouch.min`). **색만으로 상태를 구분하지 않는다** — 색 + 아이콘/부호 + 텍스트 3중(§0-1).
6. **낙관적 UI 금지.** 서버 응답 전에 목록·지도를 미리 바꾸지 않는다.
7. 명령은 `frontend/` 에서 — `flutter analyze`(무경고) · `flutter test` · `dart format --set-exit-if-changed lib/`.

  class RouteComparison {
    final ComparisonSnapshot? baseline;   // 없으면 이 버스·방향의 첫 계획이다
    final ComparisonSnapshot candidate;   // path = parseServerPolyline(polyline)
    final RouteDelta? delta;              // baseline 이 null 이면 null
    final int seatCapacity;

    /// ⚠️ **정원 초과를 서버가 시뮬레이션에서 죽이지 않는다**(OVERVIEW §4.4) — 비교
    /// 화면이 정원 때문에 통째로 죽으면 관리자가 왜 안 되는지를 볼 수 없다. 대신
    /// **저장(`apply`) 시점에는 400 으로 거절**하므로, 화면이 미리 경고하지 않으면
    /// 관리자는 눌러 본 뒤에야 알게 된다.
    bool get overCapacity => candidate.stops.length > seatCapacity;
    bool get isFirstPlan => baseline == null;
  }

  class RouteDelta {
    final double distanceM; final double durationS; final int stopCount;
    /// ⚠️ **음수가 개선이다.** 부호를 뒤집어 읽으면 화면이 정반대를 말한다.
    bool get isImprovement => distanceM < 0 || durationS < 0;

    /// `▼ 1.2km 감소` · `▲ 5분 증가` · `변화 없음`. 화살표·부호·낱말을 **함께** 낸다 —
    /// 색만으로 구분하지 않는다(§0-1).
    static String label(double value, String Function(double abs) format) {
      if (value.abs() < 0.5) return '변화 없음';
      return value < 0 ? '▼ ${format(-value)} 감소' : '▲ ${format(value)} 증가';
    }
  }
  ```

  // lib/features/routing/application/roster_simulation_controller.dart
  class RosterSimulationState {
    final int busId; final RouteDirection direction; final DateTime? serviceDate;
    /// studentId → 변경안. **Map 이라 같은 학생을 두 번 건드려도 마지막 것만 남는다** —
    /// List 로 쌓으면 `MOVE` 뒤 `REMOVE` 한 학생이 서버에서 되살아난다.
    final Map<int, StudentOverride> overrides;
    /// 마지막 비교 결과. 편집이 일어나면 **즉시 버린다** — 낡은 비교를 남기면 관리자가
    /// 지금 목록과 다른 안을 적용한다(전역 제약 6).
    final RouteComparison? comparison;
    final bool applied;
  }

  class RosterSimulationController extends AsyncNotifier<RosterSimulationState> {
    /// 응답 순서를 가리는 표. 버튼 비활성만으로는 부족하다 — 이중 탭·엔터 연타가
    /// 프레임 사이로 들어온다.
    int _requestSeq = 0;

    void configure({required int busId, required RouteDirection direction,
        DateTime? serviceDate}) { … }               // 다이얼로그 initState 에서 1회
    void addStudent(int id, double lat, double lng) { … }   // ADD
    void removeStudent(int id) { … }                        // REMOVE
    void moveStudent(int id, double lat, double lng) { … }  // MOVE
    void undo(int id) { … }                                 // overrides 에서 제거

    Future<void> compare() async {
      final current = state.value;
      // ⚠️ 이미 계산 중이면 그냥 돌아간다. 연타를 흘려보내면 외부 경로 API 호출량이
      // 배로 늘고, 늦게 온 응답이 최신 결과를 덮어쓴다.
      if (current == null || state.isLoading) return;
      final seq = ++_requestSeq;
      state = const AsyncValue.loading();
      final next = await AsyncValue.guard(() async => current.withComparison(
          await ref.read(routingRepositoryProvider).simulate(_request(current))));
      if (seq != _requestSeq) return;   // 그 사이 새 요청이 시작됐으면 이 응답은 버린다
      state = next;
    }

    Future<void> apply() async {
      final current = state.value;
      final comparison = current?.comparison;
      // 비교를 안 본 안은 적용하지 않는다. 정원 초과도 여기서 막는다 — 서버는 400 을
      // 주는데 그걸 에러 화면으로 띄우면 원인이 안 읽힌다.
      if (current == null || comparison == null || comparison.overCapacity) return;
      state = const AsyncValue.loading();
      state = await AsyncValue.guard(() async {
        await ref.read(routingRepositoryProvider).applySimulation(_request(current));
        ref.invalidate(adminRoutePlansProvider);   // 배포까지 끝났으니 노선 목록이 낡았다
        return current.markApplied();
      });
    }
  }
  ```

## 자체 점검

### 1. 요구 6·7·8 을 어떻게 덮는가

| 요구 | 덮는 단계 | 눈으로 확인하는 지점 |
|---|---|---|
| 6 관리자 버스 정보에 **선탑자** 표기 | FE-5 S3(DTO 6필드) · S7(`PersonRow`) | 관제 → 버스 선택 → 상세 `담당` 에 사진·이름·전화 |

### 2. 이미 돼 있어 작업이 필요 없는 것

1. **버스 선택 상태와 사이드 패널 구조** — `bus_detail_panel.dart`(530줄, 미커밋)와 `admin_monitor_screen` 의 반응형 3분할이 이미 있다. **새 페이지를 만들지 않는다.**
2. **지도와 정보의 동시 노출** — 넓은 화면 `Row(목록+상세 | 지도)`, 좁은 화면 `Column(지도 | 상세)` 가 이미 구현돼 있다.
3. **폴링과 상세 조회의 분리** — 상세 계열 provider 가 전부 `autoDispose.family` 라 3초 폴링에 딸려 나가지 않는다. `busDetailProvider` 도 같은 모양만 따르면 된다.
4. **정차 그룹핑 규칙**(§5.4 · `StopKey`)과 **polyline 뒤집기** 가 이미 있고 테스트로 고정돼 있다 — FE-5 는 **옮겨 재사용**할 뿐 새로 짜지 않는다.
5. **`api_client.dart` 확장 불필요** — 필요한 두 엔드포인트가 모두 POST 다.

### 3. 소스를 읽다 발견한 — 계획과 어긋나는 사실

1. **"4개 조회를 `GET /api/buses/{id}` 하나로"는 절반만 성립한다.** `BusDetailResponse` 는 `bus`·`serviceDate`·`plans`·`roster` 4필드뿐이고(BE-P3 Step 5) **운행 세션도 승하차 기록도 없다.** 제거되는 건 `busDirectoryProvider`·`adminBusRoutePlansProvider` **둘뿐**이고 나머지 둘은 남는다. 억지로 없애면 "운행 상태"·"현재 탑승"이 사라져 화면이 후퇴한다. **BE-6 에 세션·탑승 인원을 넣으면 진짜 1건이 된다 — 팀 리드 판단 필요.**
2. **선탑자 미배정이 실제로 가능하다.** D-B 는 "시드가 보장"이지 API 강제가 아니고 `AssignmentRequest.attendantId` 는 선택 필드다(BE-7 Step 2). FE-5 S7 의 미배정 문구는 폴백 동작이 아니라 **사실 표시**로 남긴다.
3. **`_MapPanel` 이 버스를 고르면 나머지 버스를 지운다**(`admin_monitor_screen.dart:204`). 강조 마커가 생기면 지울 이유가 없고, 지금 동작은 "다른 차가 어디 있나"만 잃게 한다. 요구 7 이 명시하지 않은 변경이라 여기 적어 둔다.
4. **어댑터의 카메라 제외 규칙이 새 마커 종류를 모른다.** `_geometryOf`·`_fit()` 이 `MapMarkerKind.bus` 만 제외한다 — `selectedBus` 를 빠뜨리면 3초마다 카메라가 리셋된다. `switch` 와 달리 **컴파일러가 안 잡아 주는** 숨은 결합이다.
5. **델타와 `RoutePlan.durationLabel` 의 표기 규칙이 다르다.** 기존 라벨은 `약 7분` 처럼 `약` 을 붙이는데 그대로 쓰면 `▲ 약 5분 증가` 가 된다. `RouteDelta.label` 은 `약` 없이 절대값만 포맷한다 — 델타는 추정이 아니라 **두 계산의 차**라 얼버무릴 값이 아니다.
6. **`label` 의 빈 값 규칙이 두 API 에서 다르다.** 시뮬레이션은 값이 없으면 서버가 `"좌표 지정"` 을 채워 주지만(BE-P2 Step 4), `RosterEntry.pickupLabel`/`dropoffLabel` 은 그냥 `null` 이다(BE-P3 Step 6). 그래서 FE-5 S8 은 `'승하차지 미지정'` 을 화면에서 만들고 FE-6 은 서버 문구를 그대로 쓴다 — **한쪽에 맞춰 통일하려 들면 다른 쪽이 틀어진다.**
7. **`bus` feature 가 `RoutePlan.formatDate` 를 쓸 수 없다.** 그 static 이 `routing/domain` 에 있어 `bus → routing` 의존이 된다(C-1). FE-5 S5 는 `bus_repository.dart` 안에 private `_formatDate` 를 둔다 — 두 줄짜리 포맷 때문에 공용 파일을 하나 더 만들지 않는다.
